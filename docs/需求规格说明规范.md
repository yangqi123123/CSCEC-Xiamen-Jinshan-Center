# 系统页面「需求说明」规范化提示词

## 一、任务目标

为系统内每一个页面生成右侧【需求说明】抽屉弹窗内容。

## 二、总体要求

1. 每个页面必须独立生成一套需求说明。
2. 禁止所有页面复用同一套通用模板或相同话术。
3. 内容必须贴合当前页面真实业务功能、页面原型、PRD文档、实际页面控件及业务逻辑。
4. 不得虚构页面不存在的功能、字段、按钮、接口、状态或数据关系。
5. 只描述当前页面真实存在的交互和业务规则。
6. 数据来源只描述业务层面的模块、页面或业务数据来源，不写后端接口地址。
7. 严禁出现以下内容：
   - `mock`
   - `mock-data.js`
   - 模拟数据
   - 模拟接口
   - 原型演示数据
   - 不会真实保存
   - 不会修改数据
8. 如果页面没有某项功能，必须填写“无”，不得自行补充。

## 三、每个页面必须输出的8项内容

### 1.【需求说明】

描述当前页面真实业务功能、页面用途和解决的业务问题。

要求：

- 必须结合当前页面实际业务。
- 不得使用“用于统一管理数据”“提供便捷操作”等空泛套话。
- 不得复制其他页面的描述。
- 应说明页面管理的业务对象和承担的业务职责。

### 2.【操作入口】

写明完整菜单路径。

示例：

```text
系统管理->用户管理
系统管理->日志管理->操作日志
系统管理->日志管理->登录日志
```

### 3.【交互动作】

完整描述当前页面真实存在的交互行为，包括但不限于：

- 查询、重置、展开/收起
- 新增、编辑、删除、批量删除
- 启用/停用、状态切换
- 详情查看、抽屉弹窗、普通弹窗、确认弹窗
- 文件上传、导入、导出
- 分页、树形展开/收起、勾选
- 批量授权、取消授权
- 刷新、刷新缓存、页面跳转

必须区分：

- 查询筛选区域交互
- 列表区域交互
- 新增/编辑抽屉交互
- 详情抽屉交互
- 删除确认交互
- 批量操作交互

页面不存在的交互不要填写。

### 4.【数据来源】

只描述业务层面的数据来源，不写接口地址。

必须说明：

- 当前页面主列表数据来自哪个模块或业务页面。
- 下拉选项、树形数据、授权数据、关联数据来自哪个模块。
- 当前页面与其他页面是否存在数据联动。
- 当前页面的数据变化会影响哪些页面或模块。
- 其他页面的数据变化是否会影响当前页面。

示例：

```text
角色管理页面的授权用户取自用户管理模块中状态为正常的用户数据；角色权限节点取自菜单管理模块；角色停用后会影响关联用户的菜单访问权限。
```

严禁写：

- 使用mock数据
- 使用mock-data.js
- 使用模拟接口
- 使用页面脚本中的模拟数据
- 当前数据仅用于演示

### 5.【状态流转】

描述当前页面真实存在的业务状态变化和触发条件。

必须使用以下格式：

```text
在【具体操作场景】下，状态由【原状态】流转为【新状态】。
```

示例：

```text
用户点击状态开关时，用户状态由“正常”流转为“停用”。
用户重新启用账号时，用户状态由“停用”流转为“正常”。
用户提交新增公告并保存成功时，公告由“草稿”流转为“正常”。
登录成功时，登录结果由“认证中”流转为“成功”。
操作执行失败时，日志结果由“执行中”流转为“失败”。
```

如果当前页面不存在业务状态流转，必须填写：

```text
无
```

### 6.【顶部统计卡片说明】

如果页面存在顶部统计卡片，必须说明每张卡片的具体统计规则和数据来源，按页面真实展示或实际计算的指标编写。根据页面中实际指标写明公式，如同比/环比等，不得虚构或补充。

示例：

```text
在线设备：统计设备管理中状态为“在线”的设备数量。
用户总数：统计用户管理中的全部用户数量。
正常用户：统计用户状态为“正常”的用户数量。
```

如果页面不存在顶部统计卡片，必须填写：

```text
无
```

### 7.【输出结果】

描述用户完成当前页面操作后，系统最终产生的真实结果，包括但不限于：

- 新增数据记录
- 更新业务数据
- 删除数据记录
- 修改业务状态
- 更新权限关系
- 更新组织关系
- 刷新缓存
- 生成导出文件
- 导入数据
- 打开详情抽屉
- 跳转指定页面
- 更新其他模块的可选数据
- 影响其他页面的展示或业务权限

不得只写“操作成功”等笼统描述，必须说明具体产生的业务结果。

### 8.【字段说明】

必须使用以下固定表头：

| 字段名称 | 类型 | 是否必填 | 默认值 | 取值范围 |
|---|---|---|---|---|

要求：

1. 查询筛选区域的每个组件必须单独列一行。
2. 新增弹窗或抽屉中的每个组件必须单独列一行。
3. 编辑弹窗或抽屉中的每个组件必须单独列一行。
4. 详情抽屉中的每个展示字段必须单独列一行。
5. 列表中仅展示、不可编辑的字段也必须单独列出。
6. 表格中的每个字段必须单独列出，不得合并成“列表信息”一行。
7. 分页、批量选择、全选等实际组件也必须说明。
8. 不得使用“等字段”“相关信息”“多个字段”等笼统描述。
9. 字段必须以当前页面真实存在的组件和字段为准。
10. 同名字段在筛选区、表单和列表中用途不同，应分别列出，例如：
    - 用户账号（查询）
    - 用户账号（新增/编辑）
    - 用户账号（列表展示）

## 四、字段类型规范

### 1. 单行文本输入框

类型填写：`文本`。

取值范围必须写最大输入字符数，例如：`最多50个字符。`

### 2. 多行文本框/文本域

类型填写：`多行文本`。

取值范围必须写最大输入字符数，例如：`最多200个字符。`

### 3. 下拉选择组件

类型填写：`下拉`。

取值范围必须先写枚举来源，再完整列出所有选项。

```text
来源：固定写死；选项：["正常","停用"]
来源：数据字典【user_status】；选项：["正常","停用"]
来源：后端接口返回；选项：部门管理中的正常部门节点
```

### 4. 单选框组件

类型填写：`单选`。

取值范围必须写枚举来源，并完整列出所有选项。

```text
来源：固定写死；选项：["目录","菜单","按钮"]
```

### 5. 复选框多选组件

类型填写：`多选`。

取值范围必须写枚举来源，列出全部可选值，并注明“可多选”。

```text
来源：后端接口返回；选项：菜单管理中的全部菜单权限节点，可多选。
```

### 6. 数字输入框

类型填写：`数字`。

取值范围必须说明最小值、最大值（如有）以及支持整数还是小数。

```text
整数，≥0。
支持两位小数，0≤数值≤100。
```

### 7. 日期选择器

类型填写：`日期`。

取值范围必须说明日期限制，例如：

```text
开始日期至结束日期，不允许选择未来日期。
```

### 8. 日期时间选择器

类型填写：`日期时间`。

取值范围必须说明时间范围限制，例如：

```text
开始时间至结束时间，不允许选择未来时间。
```

### 9. 开关组件

类型填写：`布尔`。

取值范围固定填写：

```text
true开启、false关闭。
```

### 10. 图片/文件上传组件

类型填写：`文件`。

取值范围必须说明文件格式、单文件大小限制和最多上传数量。

示例：

```text
xlsx或xls格式，单文件不超过10MB，最多上传1个文件。
```

### 11. 仅列表展示字段

类型填写：`列表展示`。

取值范围写明字段业务含义和数据来源。

示例：

```text
取自用户管理的用户状态，展示“正常”或“停用”。
```

### 12. 分页组件

类型填写：`分页`。

取值范围写明默认页码、默认每页条数、可选每页条数和页码限制。

示例：

```text
默认第1页，每页10条，可选10/20/50条，页码≥1。
```

## 五、固定输出格式

每个页面必须单独输出一套，不得合并页面。

```markdown
# 页面名称：用户管理

## 1.【需求说明】

填写当前页面独立的业务需求说明。

## 2.【操作入口】

填写完整菜单路径。

## 3.【交互动作】

填写当前页面真实交互动作。

## 4.【数据来源】

填写真实业务数据来源及页面联动关系。

## 5.【状态流转】

填写状态变更逻辑；无状态时填写“无”。

## 6.【顶部统计卡片说明】

填写统计卡片规则；无统计卡片时填写“无”。

## 7.【输出结果】

填写用户完成操作后产生的实际结果。

## 8.【字段说明】

| 字段名称 | 类型 | 是否必填 | 默认值 | 取值范围 |
|---|---|---|---|---|
| 示例字段 | 文本 | 是 | 空 | 最多50个字符 |
```

## 六、生成前检查要求

输出每个页面前，必须检查当前页面的：

- 菜单路径
- 页面标题
- 查询字段
- 操作按钮
- 表格列
- 表单字段
- 抽屉字段
- 详情字段
- 下拉选项
- 单选选项
- 多选选项
- 状态值
- 分页组件
- 导入导出功能
- 批量操作功能
- 页面与其他模块的数据联动关系

## 七、禁止事项

禁止：

1. 所有页面使用相同的需求说明。
2. 使用通用模板替代页面真实业务分析。
3. 复制粘贴其他页面的字段说明。
4. 虚构页面不存在的字段或功能。
5. 把多个字段合并写成一行。
6. 遗漏列表展示字段。
7. 遗漏筛选字段。
8. 遗漏抽屉和弹窗字段。
9. 遗漏分页、全选、批量操作等组件。
10. 写后端接口地址。
11. 写mock、mock-data.js或模拟数据相关内容。
12. 把“无”替换成猜测内容。
13. 使用“相关数据”“其他字段”“若干选项”等模糊表达。
14. 用统一套话描述所有页面。
15. 描述页面不存在的导出、上传、分页、弹窗或批量操作。
16. 将多个字段、多个选项或多个状态笼统概括。
