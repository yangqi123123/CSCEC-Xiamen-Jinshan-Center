# 智能物联控制台独立页面拆分设计

## 目标

将 `web/iot-console-prototype.html` 中的单页 IoT 运维控制台拆分为九个独立 HTML 页面，全部存放在 `web/pages/lot/`，完整保留原型功能、字段和 Mock 数据，同时将视觉与交互壳层统一到 `web/pages/system/user.html`。

## 导航结构

在现有“工作台 / 设备管理 / 系统管理”侧栏中新增“智能物联”一级菜单，包含九个二级菜单：

1. IoT 总览：`overview.html`
2. 接入管理：`integration.html`
3. 设备管理：`devices.html`
4. 物模型：`models.html`
5. 点位映射：`mapping.html`
6. 采集任务：`tasks.html`
7. 运行监控：`monitor.html`
8. 指令中心：`commands.html`
9. 告警事件：`alarms.html`

每个菜单必须打开独立 HTML 文件，不使用锚点切换或单一 HTML 内的多页面容器。

## 文件职责

- 九个 HTML 文件：承载各自页面标题、指标、操作区、表格或总览模块，并加载共享后台壳层。
- `iot-common.css`：只补充 IoT 页面需要、现有 `tob-ui.css` 尚未覆盖的布局和状态样式。
- `iot-common.js`：集中保存共享 Mock 配置、抽屉表单模板、提示反馈和公共点击交互，不负责把九个页面动态塞入一个容器。
- `app/config/menu.js`：新增“智能物联”一级菜单与九个独立页面路由。
- `app/components/sidebar.js`：补充智能物联一级菜单图标，沿用现有展开、选中和路由标签逻辑。

## 页面内容

### IoT 总览

保留接入系统、设备总数、今日采集点、未处理告警四项指标；接入系统状态表、设备运行概况表、快捷入口和最近运行事件；顶部“新增接入”“注册设备”操作。

### 八个业务列表页

完整保留原型中每页标题、说明、四个统计指标、页面主操作、列表字段、四条 Mock 数据、状态表达和详情操作：接入管理、设备管理、物模型、点位映射、采集任务、运行监控、指令中心、告警事件。

## 交互保留

- “新增接入”“注册设备”“创建物模型”“新增映射”“新建采集任务”“发起指令”“告警规则”打开对应右侧抽屉。
- 快捷入口打开相应抽屉；执行采集任务显示静态成功提示。
- 接入详情打开包含基本信息、HTTP 基础连接、接口目录、回调配置、设备列表和运行日志语义的详情抽屉。
- 接入详情中的“新增接口”打开 HTTP 接口配置抽屉，保留请求参数、认证覆盖、响应映射、超时和失败处理字段。
- 列表详情、筛选、保存、取消、关闭均提供静态反馈；不调用真实接口，不写数据库。

## UI 对齐

- 复用 `tob-ui.css`、共享侧栏、共享头部、共享抽屉和现有 Font Awesome 图标资源。
- 页面背景、卡片、筛选区、按钮、表格、分页、状态色、间距和低圆角严格参照 `web/pages/system/user.html`。
- 右侧抽屉使用固定头部、滚动主体和固定底部操作区。
- 侧栏宽度、品牌区、顶部路由标签、主题切换和收起行为不改变。
- 桌面端保持中高信息密度；窄屏允许指标换行、表格横向滚动，避免文字和按钮重叠。

## 准则约束

- 仅做产品静态 HTML 原型，全部数据使用 Mock。
- 每个界面独立 HTML，不实现后端、真实协议连接、动态脚本解析或规则引擎。
- 优先复用已有组件，功能之外不重构现有页面。
- 每次修改后检查中文编码、脚本语法、链接和页面结构。

## 验收

- `web/pages/lot/` 存在九个可独立打开的 HTML 页面。
- 共享侧栏出现“智能物联”一级菜单和九个二级入口，当前页选中态正确。
- 原型的所有 Mock 数据、列表字段、按钮、抽屉表单和反馈均可在对应页面找到。
- 页面不再依赖 `iot-console-prototype.html` 的锚点切换逻辑。
- 九页 JavaScript 无语法错误，页面链接与静态资源均可访问。
- 桌面和窄屏下无主要内容重叠、裁切或不可操作区域。
