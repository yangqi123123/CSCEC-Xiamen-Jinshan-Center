# codex准则

1. 先想再写 - 亮出假设，别藏困惑
2. 简单优先 - 最少代码，零投机
3. 手术式修改 - 只改必须改的
4. 目标驱动 - 定义可验证的成功标准
5. 模型只做判断 - 别拿 LLM 做路由重试
6. Token 预算是硬约束 - 超了就总结重启
7. 冲突选边站 - 别折中取平均
8. 先读再写 - 看完调用方和工具函数再动手
9. 测试验证意图 - 不是验证行为
10. 每步设检查点 - 说不清当前状态就停下
11. 遵循项目规范 - 哪怕你不喜欢
12. 失败要响亮 - 不确定就说出来，沉默最糟
13. 仅从产品设计角度输出HTML页面需求，无需考虑后端技术实现，页面全部使用Mock模拟数据
14. 所有改动遵循最小代码改动原则，只改动我要你改的功能部分代码，其他代码不要动
15. 每完成一次代码修改动作，检查是否生成了乱码，若有则改正
16. 每个界面应作为独立的 HTML 文件存放，不将所有页面塞入同一个文件中
17. 原型高效率原则 — 做原型时尽量降低页面 Token 消耗：
    - 优先复用现有组件与页面结构，不重复生成相似模块
    - 保持静态展示优先，只实现核心交互（新增、编辑、删除、切换、弹窗），减少复杂动画、冗余状态和重复逻辑
    - 列表数据使用模拟数据即可，不做深度接口联调
    - 统一使用已有样式规范与组件库，避免大面积重构页面
18. 管理后台筛选栏公共规范：一行最多展示 4 个筛选条件；超过 4 个时默认隐藏多余条件，并提供“展开/收起”按钮；仅有一行筛选条件时不显示该按钮。筛选栏操作按钮统一按“展开/收起、重置、搜索”顺序排列，重置使用次级按钮，搜索使用主按钮，位置和样式对齐“用户管理”页面。
18. 菜单目录规范 — 每个一级菜单必须对应 `web/pages/<一级菜单>/` 独立文件夹；其下每个二级菜单必须使用独立的 HTML 文件，禁止通过同一个页面的查询参数承载多个菜单界面；页面之间共享的样式、组件和模拟数据统一放在 `web/assets/`、`app/components/`、`app/config/` 或 `app/data/` 中。
19. 列表工具栏规范 — 不得放置“刷新”“全屏”“列设置”按钮；仅保留与当前业务相关的筛选、导出、新增、删除等操作。
